# safeCare

家庭保单速查：把冗长的保险合同拆成**可溯源**的结构化保障要素，需要时用一句话问出「这个情况报不报、报多少、依据哪一条」。

规划见 [`docs/PLAN.md`](docs/PLAN.md)，字段契约见 [`docs/FIELDS.md`](docs/FIELDS.md)。

## 当前进度：M2（医疗/重疾）

已实现：PDF 上传 → sha256 去重 → 逐页文本层提取 → 原文/提取文本双视图 → SQLite 落库；条款切分与分类、目录对账、保障表（范围 / 分档比例 / 年度与续保总限额 / 等待期）；DeepSeek 结构化增补（脱敏 → 引文反查 → `clause_ai` + `exclusion`/`term`）；速查卡（报不报 / 报多少 / 还得满足什么）、点 P 页码跳原文并高亮引文、待复核队列。

未实现（按计划下一步）：意外险与寿险模板（M3）、检索问答（M4）。

## AI 与本地规则的关系

**AI 结果为主，本地规则只做增量**：模型给出的条款类别、摘要、要点直接展示；模型没覆盖的条款（或没配 key 时）才用本地规则的结果兜底，界面上分别标为「保障要点（AI 抽取）」与「保障表（本地规则补充）」。

- 送出去的内容：条款编号、标题、已脱敏的条款正文。
- 脱敏：姓名 / 证件号 / 电话 / 保单号 / 银行卡 / 地址 → 占位符，映射只存本地 `redaction_map`；出口再校验一次，仍命中标识符就整批阻断。
- 引文反查：模型给的每条 `quote` 必须能在条款原文里定位（容忍空格标点，阈值 0.9），对不上直接丢弃，不写进库。
- 配置：把 `.env.example` 复制成 `.env` 并填 `DEEPSEEK_API_KEY`。不配也能用，只是没有 AI 要点。

## 运行

需要 **Node ≥ 22.5**（用到内置 `node:sqlite`）。本机默认 `node` 是 v10，跑不起来，先切到一个新版：

```bash
# 方式一：nvm-windows（可能需要管理员权限）
nvm use 24.19.0

# 方式二：只在当前 shell 前置 PATH
export PATH="/c/Users/iniu/nvm/v24.19.0:$PATH"
```

然后：

```bash
npm install
npm run dev        # 打开终端里打印的地址（本机环境设了 PORT=64029，不会是 3000）
```

冒烟测试用的示例 PDF（ASCII 文本，3 页）：

```bash
npm run sample     # 生成 data/sample/sample-policy.pdf
```

## 数据位置

全部留在本机，且已被 `.gitignore` 排除：

- `data/safecare.db` — SQLite 库（文档、页面文本、条款、保单、脱敏映射表）
- `data/uploads/<id>.pdf` — 保单原件

`data/` 里是姓名、证件号、健康状况，**不要提交、不要共享**。

## 技术要点

- 抽取引擎：本地规则先跑，再用 DeepSeek（`lib/ai/`）做增补，调用前强制脱敏（`docs/PLAN.md` §8.1），出口再做一次正则校验，仍命中身份证/手机号就阻断。
- PDF 解析用 `pdfjs-dist` 的 legacy 构建（CJS），按基线还原行，中文逐字 item 不补空格。
- 只支持有文本层的电子保单；扫描件 OCR 不在 MVP 内。

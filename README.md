# safeCare

家庭保单速查：把冗长的保险合同拆成**可溯源**的结构化保障要素，需要时用一句话问出「这个情况报不报、报多少、依据哪一条」。

规划见 [`docs/PLAN.md`](docs/PLAN.md)，字段契约见 [`docs/FIELDS.md`](docs/FIELDS.md)。

## 当前进度：M2（医疗/重疾/意外）

已实现：PDF 上传 → sha256 去重 → 逐页文本层提取 → 原文/提取文本双视图 → SQLite 落库；条款切分与分类、目录对账、保障表（范围 / 分档比例 / 年度与续保总限额 / 等待期）；AI 要素抽取（脱敏 → 引文反查 → `policy_element`）；速查卡（报不报 / 报多少 / 还得满足什么）、免责按类归并、要素检索、点 P 页码跳原文并高亮引文、待复核的确认/修正/忽略；理赔实操页（报案时限 / 材料清单 / 核定时限，都带页码）。

首页就是**保单管理**：上传过的保单连同 PDF 原件都存在本机，列表按险种分组，可按产品名 / 公司 / 保单号 / 被保险人搜索，并显示保险公司、保单号、被保险人、保障期间、保费、等待期，以及条款数、责任数、免责数、AI 要点数和待复核数；每份保单可以进速查卡、进估算、重跑 AI，也能展开表单修正抽取错的字段，或删除（库里按外键级联清掉条款与要点，磁盘上的 PDF 一并删）。

估算是两条路并行、结果并排展示：

- **按条款计算**（`lib/estimate.ts`，纯算术）：扣掉社保/公费/其他补偿 → 按附表的分档比例逐段算 → 用每期累计限额或该责任的保额封顶；等待期内、命中免责、就诊范围不符直接判 0 并给出条款依据。确定性、可复现，每一步都能点回原文。
- **AI 独立分析**（`lib/ai/claim.ts`）：同一份条款原文 + 同样的情况交给 DeepSeek，独立给结论和金额；提示词里**故意不放本地算出的数字**，避免模型照抄。引文同样要反查通过，不通过的直接丢弃；模型填的金额与它自己推理里最后算出的金额不一致时，界面上会单独标出来。

估算不构成理赔结论：没考虑医院等级与「合理且必要」的核定；分项限额只认合同里明写的类别（如住院耐用医疗设备 2 万元），没填该类金额的不扣；《骨折或关节脱位给付比例表》这类分部位比例需要你按条款附表查到比例后手动填（见下方「分项限额与给付比例表」）。

未实现（按计划下一步）：检索问答（M4）、扫描件 OCR。

## 要素抽取：AI 抄录 + 本地归类

不靠正则认版式：**整篇按页分批送给模型，让它把「保什么 / 不保什么 / 赔多少 / 什么时候生效」的原文成段抄成 JSON**（每条带页码和逐字引文），再由本机代码做确定性的事：脱敏、引文反查（对不上直接丢）、归类（免责/限额/比例/等待期…）、去重、冲突标记。所以换家保险公司、换个险种，只是换一份原文，不需要重写模板。

- 落库：`policy_element`（一条要素一行，带 `quote` + `page_no` + `clause_id`），速查卡三栏、「免责条款 · 按类看」、「全部要素」都读这张表。
- 责任表 `coverage` 不互斥：附表规则切出来的行（比例最准）保留，AI 抽到的同名责任合并进去、不同名追加；只有 AI 也认出了责任、规则却一条没切到时，才整表换成 AI 的。
- 保单摘要（只有 2 页、没有条款正文的那种）用规则解析「责任名称 + 每人/份保额」表，`lib/summary-table.ts`，比例与免赔额从同段说明里取。
- 免责按发生情形归成十几类（`lib/elements.ts` 的 `EXCLUSION` + `groupExclusions`），只为了一屏看全，不改原文；认不出的落「其他免责」。
- 降噪：疾病定义章节里逐病的医学指标不算保单要素；费率调整、核定时限、退保时限这类流程也不收（其中报案/材料/核定这些理赔流程单独归到理赔实操页）。
- 冲突不替模型选：同一个标签出现两个值（如等待期 90 天 / 30 天），两条都留、都标「待复核」，在详情页可以**原样确认 / 改对保存 / 忽略这条**；忽略的要素不再进速查卡和计数，改动前后都写进 `element_review`。
- 版本可追溯：每次抽取把模型、`PROMPT_VERSION`、token 数、状态写进 `extraction_run`，详情页显示「上次抽取」那一行。
- 兜底：没配 key 或模型整批失败时，本地规则（条款切分、保单信息、附表保障表、保单摘要）照旧出结果，界面自动切到老视图。

- 送出去的内容：逐页正文（保单号、姓名、证件号、电话、地址已替换成占位符）。
- 脱敏：姓名 / 证件号 / 电话 / 保单号 / 银行卡 / 地址 → 占位符，映射只存本地 `redaction_map`；出口再校验一次，仍命中标识符就整批阻断。
- 引文反查：模型给的每条 `quote` 必须能在它声称的那一批页面里定位（容忍空格标点，阈值 0.9），对不上直接丢弃，不写进库。
- 配置：把 `.env.example` 复制成 `.env` 并填 `DEEPSEEK_API_KEY`。不配也能用，只是没有 AI 要素。

## 换一版抽取结果后，怎么知道有没有退步

`npm run eval` 把库里每份保单的抽取结果压成一份快照（要素条数、分类、免责分组、责任表、保单号/期间/等待期），和 `data/eval-baseline.json` 对比：

```bash
npm run eval                # 有变化就逐条列出并以 1 退出
npm run eval -- --update    # 确认改动是想要的，覆盖基线
```

改了提示词、归类词表或规则之后先跑它，比重新传一份保单省事得多。基线放在 `data/` 里，和保单数据一样不出本机。

## 抽取进度与断点续跑

上传后解析完就返回，AI 抽取在后台跑（`lib/extract-job.ts`），详情页轮询 `/api/documents/[id]/extract` 看进度：「第 3 / 14 批 · 12 条要素」。后台跑的好处是一份 120 页的重疾险不用让浏览器干等，关掉页面回来进度还在。

- 分批落盘：每批结果写进 `extract_batch`（页码区间 + 状态 + 结果 JSON + token），全批完成后才合并入库。
- 断点续跑：哪批失败或做到一半被打断，详情页出现「继续未完成（N 批）」，只补没抽成功的批次，已抽好的直接复用，不再花一次钱。
- 「全部重抽」会把这份文件的批次缓存作废，从头再抽一遍（改了提示词、或结果不理想时用）。
- 进度和批次状态都在库里，不看内存：进程重启、刷新页面都还能看到上次停在哪里。

## 家庭总览

`/family` 按被保险人把保单归到一起：每个人的保单数、保费、待复核数，一眼看到全家的保障结构。

- **到期提醒**：60 天内到期或已经过期的排在最上面（「1 天后到期」「已过期 3 天」），长期重疾险显示「29 年后到期」而不是一万多天。
- 期限没识别出来的显示「期限未识别」，并单独计数，不按一年期默认补一个日期。
- 每个人旁边有「一起算」，直接跳到叠加页。

## 分项限额与给付比例表

合同里有两种「藏在条款中间」的算法，现在估算是按它们算的：

- **分项限额**（`lib/sub-limits.ts`）：认「…费用的累计给付限额为 X 元/万元」「…每日限额为 X 元」两种写法。估算页会多出一个「其中：住院期间耐用医疗设备费用」输入框，填了以后超出该项限额的部分不计入可赔金额，并写明扣了多少、依据哪一条。整单总限额、保证续保总限额、「限额 = 保险金额」这类不算分项，不会被误收。
- **给付比例表**：骨折、关节脱位、残疾、烧伤这类责任是「保额 × 比例」，比例表通常在条款附册里、正文没有数字。估算页多一个「按《给付比例表》查到的比例（%）」，按保额乘出来；不填就只显示保额，不替你猜比例。
- 两个新输入也会一起发给 AI 分析接口，免得两边口径不一样。

## 多保单叠加

首页的「几张保单一起算」（`/stack`）把同一个被保险人的几份保单放一起：填一笔医疗费用，各家按自己的条款各算一遍，再分开合计。

- **报销型**（医疗费用）：几家合计不会超过自付部分，所以合计按自付封顶，并提示「各家之和超出多少」。
- **定额型**（重疾、身故、残疾、津贴）：不按花多少钱算，单独列出保额，说明通常可叠加的前提是符合合同定义。
- 每份保单只会挑一项**费用补偿型**责任来算；纯重疾/寿险没有这类责任，就只列定额项，不拿重疾保额去凑医疗费。名字里带「津贴」的算定额型（按天给，不跟费用走）。
- 没建模的：重复保险分摊约定、先报哪家、免赔额累计，页面上写明了，不装作算得出来。

## 理赔实操页

`/documents/<id>/claim` 把合同里「怎么报」的三段摘出来：多久内报案、要交哪些材料、保险公司多久给答复（含材料不全时的补充通知、核定、给付、拒赔通知），每一条都带条款号与页码，点开跳回原文并高亮。

- 规则：`lib/claim-guide.ts`。只认讲「保险事故通知 / 保险金申请 / 保险金给付」的段落，不靠表头文字定位清单，所以双栏错位（`提供下列证明和请资料`）也能切；`（1）` 与 `（一）` 两种编号都认。
- 不替合同做决定：合同只写「及时通知」就显示「合同没写具体天数」，条款没切出来时退回用页文本，只有一两页的电子保单直接说明「条款正文在另一份条款册里」。
- 同一份文件里既有条款又有「理赔服务指南」时，以条款写的期限为准（指南常写更严的内部时限）。

## 运行

需要 **Node ≥ 22.5**（用到内置 `node:sqlite`）。本机默认 `node` 是 v10，跑不起来，先切到一个新版：

```bash
# 方式一：nvm-windows（可能需要管理员权限）
nvm use 24.19.0

# 方式二：只在当前 shell 前置 PATH
export PATH="/c/Users/iniu/nvm/v24.19.0:$PATH"
```

然后：

```bash
npm install
npm run dev        # 只绑 127.0.0.1（本机环境设了 PORT=64029，不会是 3000）
npm test           # 纯函数与数据层单测
npm run typecheck
```

冒烟测试用的示例 PDF（ASCII 文本，3 页）：

```bash
npm run sample     # 生成 data/sample/sample-policy.pdf
```

## 数据位置

全部留在本机，且已被 `.gitignore` 排除：

- `data/safecare.db` — SQLite 库（文档、页面文本、条款、保单要素、脱敏映射表、抽取记录）
- `data/uploads/<id>.pdf` — 保单原件
- `data/eval-baseline.json` — `npm run eval` 的基线

`data/` 里是姓名、证件号、健康状况，**不要提交、不要共享**。

备份与恢复：

```bash
npm run backup     # 复制库（含 -wal/-shm）和 uploads/ 到 backups/<时间戳>/
```

恢复时把 `safecare.db*` 和 `uploads/` 拷回 `data/`，再重启 `npm run dev`。

## 技术要点

- 抽取引擎：AI 抄要素 + 本地归类（`lib/ai/extract.ts` + `lib/elements.ts`），调用前强制脱敏（`docs/PLAN.md` §8.1），出口再做一次正则校验，仍命中身份证/手机号就阻断。
- PDF 解析用 `pdfjs-dist` 的 legacy 构建（CJS），按基线还原行，中文逐字 item 不补空格。
- 数据库：SQLite + WAL，取连接时 `busy_timeout` 5s、补建缺失的表并补列，所以旧库不用手动迁移。
- 只支持有文本层的电子保单；扫描件 OCR 还没做（`document.has_text_layer` 会标出来）。
